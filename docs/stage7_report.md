## 架构与恢复

Airflow负责编排、参数、日志、失败分支和重试；Python流式解析、候选生成与事务装载；PostgreSQL保存raw/staging/integration/target/evaluation/meta六层；Scrapy保存页面响应证据；Docker Compose复现。业务库与Airflow元数据库逻辑隔离。

评论和IMDb均按批事务提交。目标数据、质量问题和检查点同事务；稳定键、唯一约束与内容哈希冲突检查共同保证幂等。gzip恢复从头顺序解压并丢弃至检查点，因此空间安全但恢复时间与检查点位置成正比。

## 实体、日期与匹配语义

ASIN代表商品版本，不是作品。一个ProductEdition可映射多个Movie；Person以nconst等外部证据及作品关系消歧，不按姓名合并。商品发售日期、作品上映年份、地区上映与标题中的数字分开；未知日期保持NULL，不补1月1日。

作品候选先以标题/别名生成，再使用年份、人物、类型和编号冲突核实。硬冲突不能被分数抵消；IMDb热度只作末级排序。人工决定优先，未有人工作出决定时，严格`rule_verified`可自动采用；歧义和证据不足不采用。

## 字段血缘与质量

每个SourceRecord保存文件/URL、记录号、字段定位和内容SHA；FieldAssertion保存原始/规范候选；AssertionDependency保存转换边；FieldSelection保存采用/冲突/缺失及理由。阶段7新增反向来源影响视图和四类可执行查询。关系证据另保存principal/crew记录、角色JSON、顺序、原始姓名和选择理由。

评论平衡为7,849,544 valid + 62,152 quarantined = 7,911,696。12个物理块缺少可靠ASIN/用户，不为凑官方数删除。页面覆盖、离线覆盖、IMDb选择性覆盖分别统计。

任务8以全部7,849,544条v3有效评论执行保守精确去重，得到7,835,611条逻辑评论和7,849,544条来源映射；12,281个重复组共减少13,933条重复记录，最大组15条。缺失映射、多重映射、有效输入外映射、孤儿和无来源逻辑评论均为0。8,420个组存在helpfulness来源差异，逻辑票数置NULL且所有来源值保留。全局有效源评论平均分为4.1000977891，逻辑评论平均分为4.0999421743；业务视图显式同时报告source/logical口径。

阶段7实跑四类血缘与五类业务查询。Resident Evil: Afterlife案例同时返回采用`tt1220634`、人工拒绝`tt0432021`、旧/新规则候选池、原始UCSD记录和IMDb字段选择；反向来源查询和person作品查询的孤儿计数均为0。补齐跨版本案例后，集成库仍为875作品、9,429人物，采用商品—作品关系增至47条；作品—人物关系11,157条、关系来源证据13,461条、字段断言101,611条、字段选择12,931条未因案例记录而重算。

迁移019随后对最终字段执行全范围审计。Airflow run `manual__final_lineage_full_20261107`在活动v3解析与`logical-review-exact-v1`去重版本上完成：31个字段/关系审计项，80,651,547个适用项中78,641,193个非空，完整来源链同为78,641,193，非空但缺来源0。2,010,354个缺值主要是未采集的商品版本字段和pending分类；8,420个冲突均为helpfulness来源差异并保留全部来源。分母仅含46部实际采用作品，未把883部候选库存冒充最终电影。四类血缘及五类业务查询在修正任务8后合集视图列名后重新实跑，无SQL错误。

## 人工评价与正式指标

development规则案例与独立评价集隔离。电影/人物v2各100对，固定随机种子、分层、排除清单、来源证据和预测。HTML盲评不显示算法预测；人工标签只有同一实体/不同实体/无法确定和理由。电影标签为42/53/5，人物标签为49/49/2。人物XLSX按冻结清单核对100/100、首次导入100、相同输入重复导入0。

选择性口径中，人工`cannot_determine`和算法`needs_review`均不进入二分类混淆矩阵，并分别报告。电影实际计分63：TP27、FP5、FN6、TN25，Precision 0.84375、Recall 0.81818、F1 0.83077；人工无法确定5、算法暂缓34，对人工明确标签覆盖63/95（66.32%）。34个暂缓项中人工正例9、负例23、无法确定2。把暂缓视为“未自动合并”时，在95个明确人工样本上TP27、FP5、FN15、TN48，Precision 0.84375、Recall 27/42=0.64286、F1 0.72973。人物实际计分98：TP48、FP1、FN1、TN48，Precision/Recall/F1均0.97959；人工无法确定2、算法暂缓0。

人物姓名构成：仅共享一个姓名词26对，其中25对人工为不同实体；完整规范姓名拼写相近3对，其中2对不同；规范化后全名相同50对，其中仅1对不同。类别允许重叠，阈值和完整重叠统计见`stage7_evaluation_results.md`。全名相同的负例只有1条，因此人物分数不能外推为系统已充分解决同名不同人。

## 资源与局限

Docker数据盘位于D盘，Airflow监控宿主Docker虚拟磁盘路径；全量任务配置最低可用空间阈值，低空间安全停止且不无限重试。主要局限：Amazon页面只做5次有界尝试、成功0，不能声称全量页面覆盖；UCSD离线元数据覆盖29.1683%；IMDb选择性装载不是五表全量镜像；principals只是主要署名。四类development案例现均有5组证据充分实例；这只满足案例展示要求，不代表页面全量或实体匹配无误。
